# 延长压力测试生命的只读安全审查

本审查没有连接硬件，也没有修改固件。建议的运行期试验设置：正常新开局、已确认 app GAME/game_enabled=1、hp>0、over=0 后，仅将匹配 ELF 的 `game_lives` RAM 变量设为 1000，用于避免机体碰撞使五分钟压力过早结束。源码、ELF 和玩法默认生命保持 10。

已核对：

- `game.c` 的 `game_lives` 为 u32，仅存储、传递、递减、零判定；不是数组索引，也不控制动态数组长度。`game_claimed` 仅将数值复制入固定 `game_if[0]`，显示确认沿原路径发布。
- `game_hud.c:50` 的 HUD2 先将生命钳位到 10；旧 HUD 在第 73 行钳位到 9。BCD 编码位数为固定 2/6，生命大值不会增大局部 `d[6]` 索引或 RTL 生命段索引。
- `enemy_config.h` 默认生命 10、受击无敌 1000 ms。只提高生命不改变受击判定、无敌期、护盾、机体碰撞、敌机/弹幕/爆炸或输入采样路径。1000 足以支撑 310 秒受击压力；无需用接近 uint32 上限的值。
- TEL hp 输出原显示确认生命，可能显示 1000/999…，而 HUD 钳位仍显示 10。应在测试记录明确这一差异，不能声称默认十条生命自然存活五分钟。

试验门控与恢复：按当前 ELF `nm` 解析的地址、大小/类型与 RAM BUILD/代码指纹核验；记录注入前后值，resume 后关闭 JTAG，确认 TEL 发布新生命值，再开始无 JTAG 压力计时。不要改 `game_display_lives`、`game_if`、flow、输入、PC 或 invulnerable 时间。结束后先通过已审查的受控 GameOver 使原显示确认 over=1，再走原 KEY3 重开，确认生命恢复 10。游戏仍存活时 KEY3 不会直接重开。

结论：未发现这项单变量测试设置导致 HUD 数组越界或整数逻辑异常的路径。它属于明确披露的测试生命扩展压力，不能替代默认生命玩法验收或自然 GameOver/实体按键测试。
